# whisper101

CLI для обработки аудиозаписей и готовых транскриптов: распознать речь, разобрать языковую практику, составить конспект встречи или оформить голосовую заметку.

Аудио обрабатывается локально через **ffmpeg → whisper.cpp**. Для задач анализа приложение отправляет в **OpenAI API только текст**. Приложение написано на TypeScript и запускается через Bun.

## Что уже умеет

| Задача       | Что получается                                                                                   | Нужен OpenAI |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------ |
| `transcribe` | Транскрипт аудиозаписи                                                                           | Нет          |
| `coach`      | Удачные фразы, грамматические замечания, естественные формулировки, словарь и исправленный текст | Да           |
| `meeting`    | Конспект встречи: итоги, решения, поручения и открытые вопросы                                   | Да           |
| `note`       | Связная структурированная заметка на основе сказанного                                           | Да           |

- Принимает один файл за запуск: аудио, например `.m4a` из диктофона iPhone, или готовый `.txt`. Другие аудиоформаты зависят от установленного ffmpeg.
- Предлагает интерактивный мастер или прямой запуск с параметрами.
- Позволяет отдельно выбрать язык записи и язык результата.
- Применяет разные задачи к готовому транскрипту без повторного распознавания.
- Создаёт проверенную копию транскрипта и использует её для анализа после подтверждения.
- Сохраняет каждый запуск в отдельную папку и выводит время этапов.
- Показывает историю запусков и создаёт локальный HTML-отчёт с аудиоплеером.

## Подготовка

Нужны **Bun**, **ffmpeg**, собранный **whisper.cpp** с программой `whisper-cli` и скачанная модель Whisper. Для разных языков используйте мультиязычную модель, без `.en` в названии.

По умолчанию проект ожидает соседнюю папку:

```text
dev/
├── whisper101/
└── whisper.cpp/
    ├── build/bin/whisper-cli
    └── models/ggml-medium.bin
```

Из корня проекта:

```bash
bun install
# Только если .env ещё нет:
cp -n .env.example .env
```

Для анализа задайте `OPENAI_API_KEY` в `.env`, затем проверьте окружение:

```bash
bun run doctor
```

`doctor` проверяет наличие программ, файла модели и ключа. Он не делает API-запрос и не проверяет баланс, доступ к модели или корректность её содержимого. Для работы только с `.txt` native-инструменты не нужны, хотя `doctor` проверяет их независимо от задачи.

## История записей и просмотр

```bash
bun start
```

Главное меню предлагает обработать новый файл или открыть недавнюю запись. Для нового файла введите путь, затем выберите задачу в мастере. Можно использовать `~/Downloads/...` и пути в кавычках.

История читает папки внутри `output/`, сортирует их от новых к старым и показывает задачу и статус. Поддерживаются старые папки без `run.json`; повреждённые метаданные не мешают открыть сохранённый текст. Список разбит на страницы по 15 записей. Папки, созданные через `--out` за пределами `output/`, в список не входят.

Действия с записью:

- **Открыть HTML-отчёт** - просмотр результата с аудиоплеером и транскриптом. Для старых папок HTML создаётся локально, без OpenAI.
- **Прослушать аудио**, **открыть транскрипт**, **открыть папку** - через стандартные приложения системы.
- **Проверить транскрипт перед анализом** - создать отдельную копию, исправить её в системном редакторе и затем выбрать задачу.
- **Выполнить другую задачу по тексту** - новый опросник без повторного запуска Whisper.
- **Повторить анализ** - те же задача, языки и модель, после подтверждения. Для неудавшегося анализа это способ восстановления.

Доступны только действия, для которых есть сохранённые файлы. Повторный анализ требует `transcript.txt`. Для записи со статусом `running` повтор с теми же настройками не предлагается: она может ещё обрабатываться. Обычный просмотр не изменяет текст и разбор; отсутствующий `report.html` создаётся один раз. Если проверенная версия уже существует, история предлагает открыть её или продолжить проверку.

Продолжение из истории создаёт **новую** папку. В неё копируются транскрипт и доступные `audio.wav`/`transcript.json`, чтобы аудио осталось рядом с отчётом. В `run.json` сохраняется `sourceRun` - путь к предыдущему результату. Оригинальные файлы не перезаписываются.

```bash
bun start history
bun start report "output/polish-2026-09-10"
```

`report` создаёт недостающий HTML и открывает его; ключ API и Whisper не нужны. Команды открытия используют `open` на macOS и `xdg-open` на Linux. На других платформах или при отсутствии программы CLI выводит путь для ручного открытия.

### Проверка транскрипта

Откройте запись в истории и выберите **«Проверить транскрипт перед анализом»**. Приложение создаст `transcript.reviewed.txt` рядом с исходником и откроет его в стандартном текстовом редакторе. Исправьте ошибки распознавания, сохраните файл, вернитесь в терминал и подтвердите готовность. После этого мастер предложит задачу и язык результата.

`transcript.txt` остаётся неизменным. Если выйти до анализа, правки сохранятся: действие **«Продолжить проверку транскрипта»** откроет ту же копию без перезаписи. Новый запуск переносит оба варианта текста, аудио и диагностику в отдельную папку. В `run.json` будет `"transcriptSource": "reviewed"`, а HTML-отчёт покажет проверенный вариант и пометит его соответствующим значком.

## Интерактивный мастер

```bash
bun start ~/Downloads/polish.m4a
```

`bun start` и `bun run start` запускают один скрипт. Мастер последовательно спрашивает:

1. Что сделать: языковой тренер, конспект встречи, заметка или транскрипция.
2. Язык записи: определить автоматически, польский, английский или русский.
3. Язык результата: русский, английский или польский.
4. Начать ли обработку с выбранными настройками.

Выбор - **стрелками**, подтверждение - **Enter**, отмена - **Ctrl+C** или «Нет» на последнем шаге. Отмена завершает команду с кодом `130`, без создания папки результата и API-запроса.

Мастер задаёт только нужные вопросы: для транскрипции не спрашивает язык результата, для `.txt` - язык записи. Если параметр уже передан через CLI, соответствующий вопрос пропускается.

Последние подтверждённые настройки сохраняются в `.local/settings.json` и используются как начальные значения в следующем опроснике. Для сброса удалите этот файл. В нём хранятся только задача и языки, без ключей и записей.

Без интерактивного терминала используйте `--task` или короткую команду задачи.

## Запуск без опросника

```bash
# Польская практика с объяснениями на русском
bun start polish.m4a --task coach --language pl --feedback-language ru

# Английская практика с объяснениями на английском
bun start english.m4a --task coach --language en --feedback-language en

# Конспект встречи с автоматическим определением языка
bun start meeting.m4a --task meeting --language auto --feedback-language ru

# Оформить русскую голосовую заметку
bun start idea.m4a --task note --language ru

# Только локально распознать запись
bun start recording.m4a --task transcribe --language auto
```

В прямом запуске сохранённые настройки мастера не используются:

| Настройка                                | По умолчанию |
| ---------------------------------------- | ------------ |
| Язык для `coach` и прежнего `analyze`    | `pl`         |
| Язык для `meeting`, `note`, `transcribe` | `auto`       |
| Язык результата                          | `ru`         |

В мастере первый выбор языка - `auto`, если предпочтения ещё не сохранены. Для текстового входа мастер также использует `auto`: язык определяет модель по тексту. Явный `--language` имеет приоритет.

Короткие команды тоже запускаются сразу:

```bash
bun run coach polish.m4a
bun run meeting meeting.m4a
bun run note idea.m4a
bun run transcribe recording.m4a
```

## Повторная обработка текста

```bash
# Выбрать задачу через мастер
bun start "output/meeting-2026-09-10/transcript.txt"

# Оформить тот же текст как заметку
bun start "output/meeting-2026-09-10/transcript.txt" --task note

# Разобрать готовый английский транскрипт
bun start "output/english-2026-09-10/transcript.txt" --task coach --language en
```

Каждый запуск создаёт новую папку с копией текста и результатом. Whisper не запускается; при прямом запуске по пути к `.txt` аудио и диагностика из прежней папки не копируются (продолжение из истории переносит их). Поэтому длительность и оценки Whisper для такого разбора недоступны. Задача `transcribe` с `.txt` просто сохраняет копию текста.

Сохранён и прежний текстовый разбор без краткой сводки Coach:

```bash
bun run analyze transcript.txt
bun index.ts transcript.txt
```

Оба вызова работают без мастера, по умолчанию разбирают польский на русском. `analyze` - совместимая подкоманда, а не значение для `--task`.

## Language Coach

Coach показывает длительность записи, диагностику распознавания и сводку, например:

```text
🎤 2:43 · pl
✓ Естественные фразы: 7
⚠ Грамматические замечания к транскрипту: 4
💬 Более естественные формулировки: 3
📚 Полезные слова и конструкции: 5
🔎 Места для сверки с аудио: 2
```

Числа считаются по пунктам конкретного ответа; это выбранные примеры, а не исчерпывающая оценка всей речи. Пустые категории допустимы. Подробности, цитаты, объяснения и исправленный текст находятся в `feedback.md`. Объяснения и заголовки следуют языку результата; исправления и примеры остаются на языке исходного текста.

Средняя вероятность токенов Whisper **не является процентом точности**. Число токенов с оценкой ниже `0.50` - ориентир для проверки; порог не калиброван. При отсутствии оценок приложение сообщает, что они недоступны. Длительность относится ко всей записи, включая паузы.

## Файлы результатов

Пример полного запуска Coach с аудиофайлом:

```text
output/
└── polish-2026-09-10/
    ├── audio.wav
    ├── transcript.txt
    ├── transcript.json
    ├── feedback.md
    ├── report.html
    ├── coach.json
    └── run.json
```

После ручной проверки следующий запуск также содержит `transcript.reviewed.txt`; исходный результат Whisper остаётся в `transcript.txt`.

| Файл                      | Содержимое и когда создаётся                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------- |
| `audio.wav`               | Конвертированная запись: моно, 16 kHz, PCM16. Сохраняется при аудиовходе; оригинал не меняется |
| `transcript.txt`          | Распознанный текст или копия входного `.txt`                                                   |
| `transcript.reviewed.txt` | Проверенная вручную копия; создаётся по действию из истории                                    |
| `transcript.json`         | Токены, временные метки и язык из локального распознавания                                     |
| `feedback.md`             | Результат задачи анализа; отсутствует у `transcribe`                                           |
| `report.html`             | Локальный отчёт с аудиоплеером, разбором и транскриптом                                        |
| `coach.json`              | Структурированный разбор и диагностика; только у `coach`                                       |
| `run.json`                | Задача, входной путь, языки, модели, статус и время выполнения                                 |

Дата в названии папки - местная дата запуска. Повторные имена получают суффиксы `-2`, `-3` и далее, в том числе при параллельных запусках. Старые результаты не перезаписываются. `--out` позволяет задать свою **новую** папку.

Логи показывают время ffmpeg, Whisper, анализа OpenAI и общее время после опросника. В `run.json` время конвертации и распознавания объединено в `transcription`, отдельно записаны `analysis` и `total`. Статусы: `running`, `completed`, `failed`; при принудительном завершении процесса может остаться `running`.

## HTML-отчёт

После обработки приложение создаёт `report.html` рядом с результатами и выводит его путь. В отчёте есть аудиоплеер (если доступен WAV), разбор с оформлением Markdown и транскрипт для сверки. Для анализа проверенной копии отчёт показывает именно её, добавляет отметку и ссылку на `transcript.reviewed.txt`; оригинал остаётся рядом. Отчёт создаётся и для транскрипции без анализа, а при сбое - по уже сохранённым файлам. Если сбой произошёл до появления аудио или текста, отчёта может не быть.

```bash
# Открыть отчёт сразу после успешной обработки
bun start recording.m4a --task coach --language pl --open
```

HTML не загружает внешние скрипты, шрифты, изображения или аналитику. Разметка ответа очищается; произвольный HTML из транскрипта отображается как текст. Ссылки в разборе могут вести на внешние страницы только при переходе по ним.

Для переноса отчёта вместе с аудио копируйте **всю папку**, а не только HTML. В web view доступность локальных HTML и аудио зависит от правил самого приложения. Просмотр в браузере не отправляет запись в OpenAI.

В Coach наверху находятся количества выбранных примеров со ссылками на разделы. Исправления показаны парами «В транскрипте / Лучше сказать» с объяснением. Первые три замечания открыты; остальные раскрываются по нажатию. Удачные фразы и словарь с примерами выделены отдельно. Исходный и исправленный тексты свёрнуты, чтобы сразу видеть полезные выводы. Аудиоплеер остаётся рядом при прокрутке на широком экране. Отчёт всегда использует светлую тему независимо от настройки системы; на телефоне блоки выстраиваются в одну колонку.

Оформление Coach строится по `coach.json`; без корректных структурированных данных доступен обычный Markdown-разбор. Числа отражают выбранные моделью примеры, а не оценку владения языком.

Существующий `report.html` сохраняется без перезаписи. Чтобы применить новый дизайн или обновить отчёт по сохранённым данным:

```bash
bun start report "output/polish-2026-09-10" --refresh
```

Команда сохраняет предыдущий HTML в `report.backup-<id>.html`, затем создаёт и открывает обновлённый отчёт. Транскрипты, аудио и разбор остаются на месте; API не вызывается. Ручное редактирование файлов без `--refresh` не обновляет HTML автоматически.

## Параметры CLI

| Параметр                                  | Назначение                                                                                         |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `--task coach\|meeting\|note\|transcribe` | Выбрать задачу и пропустить мастер                                                                 |
| `--language auto\|pl\|en\|ru`             | Язык записи; для текста - подсказка модели. Допустимы другие короткие коды, поддерживаемые Whisper |
| `--feedback-language ru\|en\|pl`          | Язык результата анализа                                                                            |
| `--out DIR`                               | Создать конкретную новую папку результатов                                                         |
| `--model NAME`                            | Модель OpenAI для одного запуска                                                                   |
| `--open`                                  | Открыть HTML-отчёт после успешной обработки                                                        |
| `--refresh`                               | Только для `report`: обновить HTML с резервной копией прежней версии                               |
| `--cpu`                                   | Отключить GPU при распознавании                                                                    |
| `--keep-wav`                              | Совместимость со старыми командами; WAV уже сохраняется по умолчанию                               |
| `--help`, `-h`                            | Справка                                                                                            |

Не задавайте разные задачи одновременно через подкоманду и `--task`. Пути с пробелами заключайте в кавычки.

## Настройки окружения

Bun загружает `.env` при запуске из корня проекта. Не публикуйте файл с ключом.

| Переменная       | Назначение / резервное значение в коде                                    |
| ---------------- | ------------------------------------------------------------------------- |
| `OPENAI_API_KEY` | Ключ для анализа. Не нужен для `transcribe`                               |
| `OPENAI_MODEL`   | Модель OpenAI; резервное значение `gpt-5.6-luna`                          |
| `WHISPER_BIN`    | Путь к `whisper-cli`; по умолчанию `../whisper.cpp/build/bin/whisper-cli` |
| `WHISPER_MODEL`  | Файл модели; по умолчанию `../whisper.cpp/models/ggml-medium.bin`         |
| `FFMPEG_BIN`     | Команда или путь к ffmpeg; по умолчанию `ffmpeg` из PATH                  |

В `.env.example` сейчас указана `gpt-5.6-terra`: после копирования примера будет использоваться она. Для Coach выбранная модель OpenAI должна поддерживать Structured Outputs.

Пути Whisper разрешаются относительно корня проекта; можно задавать абсолютные пути. Для уже скачанной `large-v3` поменяйте в `.env`:

```dotenv
WHISPER_MODEL=../whisper.cpp/models/ggml-large-v3.bin
```

## Ошибки и ограничения

- Если OpenAI недоступен, уже созданные аудио и транскрипт остаются на диске. Повторите нужную задачу с сохранённым `transcript.txt`.
- Для анализа действует ограничение **100 000 символов** транскрипта. Длинный текст нужно разделить вручную.
- Приложение использует `store: false` для Responses API. Это не обещание полного отсутствия служебного хранения у провайдера.
- Whisper может неверно распознать слова или исправить ошибки говорящего. Coach анализирует текст, не произношение, акцент или уровень CEFR.
- Meeting получает инструкции не придумывать ответственных и сроки, а Note - не добавлять факты. Результаты модели стоит сверять с исходным текстом.
- Пакетная обработка папки, запись с микрофона, разделение голосов по участникам и веб-интерфейс пока не реализованы.

## Разработка

```bash
bun test
bun run typecheck
bun run format
```

Тесты используют заглушки API и опросника, не требуют ключа и не расходуют API-квоту. Prettier форматирует код и документацию. Сборка приложения не нужна: Bun запускает TypeScript напрямую.

Основные части проекта:

```text
src/
├── cli.ts           # параметры и точки входа
├── history.ts       # чтение сохранённых записей
├── library.ts       # главное меню и действия с историей
├── report.ts        # безопасный локальный HTML
```
